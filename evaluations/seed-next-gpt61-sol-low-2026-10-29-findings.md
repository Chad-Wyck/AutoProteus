## Conditions and limits

The starter fingerprint is `645d2222c5f7f6e92ad5f2ca964f7584e07b47ea4d410872e98a61009eb7bb0d`, identical to the latest
Qwen revision cohort. Hashing, canonical JSON formatting and CSV preview each
received three scheduled repetitions, with a separate second extension from
the independently verified first package. Each new chain starts from the
frozen starter. Frozen task wording, fixtures, grading contracts, task reminders,
public verifier disclosure and resource allowances match the Qwen cohort.

Sol used the protected production Responses adapter, 128K configured context,
4096 output tokens per call and `reasoning.effort=low`. Both requests and returned
metadata confirm low on every call. Each feature task retained 128 actions,
65536 generated tokens and 3600 shared seconds across development, independent
checking, activation and use. Commands ran only inside disposable VMs. Study
internet access stayed off; app preferences were unchanged. No LoRA was used.

Responses does not send the local model's temperature or RNG seed. Its three
repetitions therefore use provider-default sampling, with the old seed schedule
retained only as case labels. This is a capability comparison across distinct
models and transports, not a controlled sampling or quantization experiment.
First-attempt acceptance permits model-led debugging during its task allowance;
it does not claim that every initial code edit was perfect.

These are three familiar, prescribed capability families. The results establish
successful directed growth on this suite, not autonomous discovery of arbitrary
new capabilities or general reliability on unseen tasks.

## Preserved integration interruption

The first integration run passed ordinary tasks but exposed an observer bug:
the host history recorder assumed a Chat Completions `messages` field. Its
exception suppressed downstream request records and sent-request spending
observations. The operator stopped it before a first-extension verdict. Its
original plan, results and interrupted-attempt receipts remain under
`.data/openai-sol-low-20261029/full`; no failed candidate was repaired or retried
within the fresh qualification cohort.

The recorder now handles Responses `input` items. Downstream accounting is
forwarded even on recorder failure, and a provider response or complete usage
also proves that a call was sent. An end-to-end host-path regression catches
the original defect. Validation after the fix: **542 ordinary tests, 66 skipped,
all passing**, plus the frozen study's real-VM grader and protected-starter
calibration. The editable seed did not change for API compatibility.

The interrupted run has 38 reported calls (estimated
$0.08) and 1 uncertain call charged a full
configured envelope for the guard. Its conservative carry-in is
$0.68. The final conservative guard total, including
that carry-in and ignoring fresh-study cache discounts, is
**$7.35**, below the original $25 cap. Original inaccurate
sent flags are preserved rather than rewritten; reconciliation is separate.

## Interaction-log retention update

After verification, the user requested removal of Sol's raw interactions to
prevent accidental future training use. Raw provider traces, saved conversations,
event journals, conversation summaries and inference blobs were deleted: 2,091
files, 52,010,208 bytes. The three published reports and 5,277 retained original
result files were verified unchanged. Results-only artifact manifests preserve
file identities without conversations. Historical statements about trace coverage
above describe the completed checks before removal; the raw traces are no longer
available for a new transcript audit.

The retained private study and its Sol-produced candidate artifacts are marked
excluded from training. Scores, costs, frozen plans, grader receipts and reference
artifacts remain. Local Qwen curation excludes this entire study.
