# Activation placement and cumulative growth comparison

The ordinary seed remains the control. The opt-in `activation-history` copy
changes only activation-state placement in `autoproteus/context.py`; its study
broker suppresses the controller's fallback reinsertion. The same
state stays beside the latest internal activation boundary, with an early
conversation fallback if trimming removes that boundary. It remains included
in context budgeting. System guidance, README, human instructions, permissions,
tools and resource limits are otherwise identical. This is a coupled seed and
controller presentation experiment; no benefit has been established.

For newly prepared plans on v0.10.0, the control already places activation state
early beside the original task. The variant instead places it beside the exact
activation boundary. Historical frozen plans retain their older control and
must not be relabelled as trials of the new seed; regenerate plans after changes.

The first study uses Qwen3.5 9B Q6, 128K context, 4K responses, temperature 0.6,
top-p 0.8, top-k 20, thinking off, the production native adapter and no LoRA.
Public internet is explicitly disabled for both offline arms. The normal app's
internet preference is unchanged.

Three paired chains run in A/B, B/A, A/B order, with matched input bytes:

1. Add and register `sha256_file`, preserve the starter, pass protected and
   independent checks, activate, and use it to save and inspect `hash.json`.
2. Only after that unassisted workflow completes, continue the same session and
   exact grown seed. Add and register `inventory_files`, retain the hash tool
   and every prior test, pass independent checks, and activate again.
3. Use both tools on a new directory to produce an exact default inventory and
   a per-file hash audit. Preserve inputs and the first receipt, inspect both
   outputs, and explicitly finish.

Each extension has 60 minutes, 128 model actions and 65,536 generated tokens,
shared by its development, parent-absence check, all independent grading,
retention checks, activation and final use. Cleanup overruns are recorded.
Each eligible second extension starts a fresh equal allowance. A first-stage
failure leaves its second extension untested; it is not replaced with a supplied
or repaired parent. Complete-chain scores retain all three scheduled chains in
each arm's denominator. Conditional second-pass denominators are also reported.

Before inference, both starters must pass protected regressions. Two reference
implementations must pass, and deliberately absent, wrong-schema, wrong-default,
wrong-byte-count, wrong-digest, symlink, traversal and exact-boundary controls
must fail. The inventory grader tests exactly 200 and 201 files in both modes
and requires both advertised arguments to be optional. Hash checks include
the exact 1 MiB boundary. Scripted actual-VM activation checks verify delivery
through the seed, worker and host broker, without a model.

Report independent feature acceptance, correct saved artifacts, explicit task
completion, functional use and direct native use separately. Compare efficiency
only among matched complete successes with complete measurements. No hidden
grader feedback, candidate repairs, automatic retries or extra final-use coaching
are delivered. Infrastructure failures and operator interventions remain separate.

The frozen plan, copied sources, calibration receipts, model/runtime identities,
provider traces, complete journals and checkpoints are saved under
`.data/activation-chain-v082-20261024/`. The owned local runner monitors only
stdout while work is active; reading mutable live snapshots can interfere with
Windows atomic file replacement. The study does not modify app preferences or
promote a candidate into the user's default seed.

The user stopped that first batch after nine actions, before any chain finished.
Its evidence remains an operator interruption. The fresh restart lives in
`.data/activation-chain-v082-restart-20261024/`, retaining the exact same two
seed identities, tasks, model settings and budgets. Its frozen plan declares
the primary decision rule before inference: complete chains out of three per
arm, with conditional second-pass denominators separate. A lead is exploratory;
default promotion requires new contracts and another model. Ties establish no
effectiveness winner.

Four compressed, unmodified model candidates under
`evaluations/fixtures/grader-candidates/` supplement the constructed controls:
three real failures (required optional path, missing file cap, nonboolean
recursion) and one independently verified positive. Their byte/source hashes
are checked before guest-only execution. Each expected defect must be observed,
so an incidental import or setup failure cannot substitute for detecting it.
The experiment index records starts, completed chains, costs and terminal
outcomes without changing historical frozen scores.
